비전 모델 경량화 on Jetson Orin Nano

ResNet-18 한 모델을 CPU 양자화와 TensorRT로 각각 최적화하고, 지연시간·모델 크기·전송 오버헤드를 같은 조건에서 실측해 비교했습니다.

    한눈에

    배치 16장 기준, GPU 연산 시간(mean).

    1. 최적화 단계별 추론 지연시간

    같은 ResNet-18을 실행 방식만 바꿔가며 측정했습니다. PyTorch로 그냥 돌린 기준선에서 TensorRT INT8까지 내려오면 배치당 연산 시간이 줄어듭니다.

    2. 빨라질수록 드러나는 전송 병목

    TensorRT 엔진의 종단 지연시간을 GPU 연산과 호스트↔GPU 데이터 전송으로 나눠 봤습니다. 연산은 5배 넘게 빨라지지만 전송 비용은 거의 그대로라, 전체에서 전송이 차지하는 비중이 로 늘어납니다. 더 낮은 정밀도로 내려갈수록 최적화 대상이 연산에서 데이터 이동으로 옮겨간다는 뜻입니다.

    3. CPU 양자화의 역설

    같은 INT8 양자화라도 CPU에서는 이야기가 다릅니다. 모델은 4배 넘게 작아지지만 이 Jetson의 CPU에서는 오히려 . 크기와 시간은 단위가 다르므로 축을 겹치지 않고, FP32를 100으로 둔 상대값으로 나란히 놓았습니다.

    4. TensorRT는 그래프를 절반으로 접는다

    ONNX 그래프에는 가 있지만, TensorRT가 엔진으로 빌드하면 로 줄어듭니다. Conv + Add + Relu처럼 연속된 연산을 하나의 커널로 합치기 때문입니다 — 잔차 블록의 덧셈까지 함께 삼킵니다. 실제로 INT8 엔진에서 처럼 묶였습니다.

    한편 엔진 내부의 Reformatting(데이터 레이아웃 변환)은 연산이 아니라 순수 오버헤드인데, 정밀도를 낮춰 연산이 빨라질수록 그 비중이 로 커집니다. 2번 차트에서 본 전송 병목과 같은 이야기가 엔진 안에서도 반복되는 셈입니다.
